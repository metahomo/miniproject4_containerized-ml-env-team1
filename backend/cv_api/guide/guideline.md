# 가이드라인 — 연계 개발자(일반 사용자)용

> 판본 v1.3 (2026-09-29 — 로그인 필수, 가입 = 일반 사용자, API 키는 운영 관리자 승인 뒤 사용) · v1.2 (2026-09-29 — 회원가입·역할(RBAC)·키 발급 추가) · v1.1 (2026-09-29) — 혼잡도 = 인원 ÷ 차량 전체 정원(research R22), 공개 주소 `/API`, 이용자·관리자 인증, 실제 대전 BIS 연동 반영

## 1. 주소와 키 (FR-16, G1)
- **공개 주소**: `https://p4.sumzip.com/API` (Swagger 시험 호출 `https://p4.sumzip.com/API/docs`, 명세 `/API/openapi.json`). 내부망은 `http://<서버>:9544`.
- **호출 키** `X-API-Key`: 모든 요청에 보낸다. **회원가입(일반 사용자) → 로그인 → «내 API 키»에서 연계 시스템마다 신청(`cvk_…`, 원문은 신청 때 한 번만) → 운영 관리자 승인** 뒤에 쓸 수 있다(승인 전 403 `KEY_PENDING`). 매뉴얼 "API 키 받기" 참고. 키는 호출 주체를 식별해 기록(FR-17)에 남기는 데만 쓰이며, 시민 안내 채널·관제 시스템·본 웹서비스가 **같은 값**을 받는다(정보 무차등).
- 호출 키로는 진단·실측·후속 차량·보기 전용 조회(`/v1/reference/*`)만 된다. 변경(`/v1/admin/*`)은 운영 관리자 키 `X-Admin-Key` 만 — 호출 키로 부르면 401(G1).
- 키가 없으면 401, 틀리면 403. 키는 코드 저장소·앱 배포본에 넣지 말고 서버 설정으로 둔다. 유출되면 운영 관리자에게 재발급을 요청한다.

## 2. 요청 규격 (FR-02)
- `POST /v1/diagnose`·`/v1/measurements` 의 `frame`: JPEG·PNG, 짧은 변 240px 이상 · 긴 변 4096px 이하, 10 MB 이하. 일괄(`/batch`)은 20장 이하.
- 규격 밖이면 진단 없이 422(G2) — 응답의 `allowed_spec` 에 허용 규격이 있다. 휴대폰 사진(HEIC 등)·큰 사진·영상은 웹 화면용 `/v1/web/*` 가 규격으로 바꿔 준다(짧은 변 240px 미만은 키우지 않고 반려).
- 정의되지 않은 필드가 들어 있으면 422 로 반려된다.

## 3. 혼잡도 계산 — 무엇을 믿고 어떻게 보이나 (FR-04, R22)
- **인원(`person_count`)**: 검출 신뢰도가 인원 세기 기준(기본 0.4, 운영 관리자 조정) 이상이고 발 위치가 관심영역(ROI) 안인 사람 수. 카메라에 보이는 사람의 추정치다 — 가려진 사람은 빠질 수 있다.
- **혼잡 %(`occupied_area_ratio`)** = 인원 ÷ **차량 전체 정원(`capacity`)** × 100. 정원을 넘으면 100 에서 멈추고 `over_capacity: true` — "혼잡 100% · 정원 초과"로 표시한다. **여유 %(`vacant_capacity_ratio`)** = 100 − 혼잡 %. **잔여 인원(`remaining_persons`)** = 정원 − 인원(하한 0).
- 권장 표시: 큰 글씨 **"30 / 45명 · 혼잡 67%"**, 보조로 "여유 33%". 여유 % 만 떼어 크게 보이지 않는다(사람 수를 함께).
- 정원이 등록되지 않은 카메라(승강장 등)는 인원만 오고 `capacity: null`, `crowding_level: uncertain`, 경고 `unknown`("정원 미등록") — 혼잡도를 "산출 불가"로 표시한다(G7).
- 차량 합산(후속 차량 실측): 차량에 달린 카메라들의 최신 유효 실측 **인원을 더해** 차량 정원으로 나눈다(`persons_sum`). 일부 카메라만 있으면 `partial_coverage` 와 커버리지(예: 2/3)를 함께 보인다.

## 4. 추정치 고지 표시 의무 (FR-10)
- 모든 응답의 `notice` 문구를 사용자에게 보이게 표시한다. 수치만 떼어 쓰지 않는다.

## 5. 경고와 "판독 불확실" 해석 (FR-08·09)
| 코드 | 뜻 | 대응 |
|---|---|---|
| blur | 영상 흐림 | 재촬영 |
| low_light | 저조도 | 재촬영 또는 참고용 |
| backlight | 역광 | 재촬영 |
| low_confidence | 셈에 든 사람의 평균 신뢰도 0.6 미만 | 수치는 참고용. 확정 등급 없음 |
| occlusion | 승객 겹침 | 인원 과소 가능 — 만원일수록 적게 센다 |
| roi_stale | ROI 검증 필요 | 운영 관리자 갱신 대기 |
| partial_coverage | 차량 카메라 일부 누락 | 커버리지 표시 |
| unknown | 모델 응답 불가, 정원 미등록 등(`detail` 참조) | 판독 불확실 |
- `crowding_level: uncertain` 이면 `is_reference_only: true` 다. 이 값을 확정 등급처럼 표시하지 않는다("참고 30 / 45명").

## 6. 비식별·프레임 미보관 (FR-11)
- 서비스는 얼굴·신원을 추출하지 않고 원본 프레임을 저장하지 않는다(요청 메타만). 연계 시스템도 진단 목적 외 프레임 보관을 피한다.

## 7. 성능 기준·호출 빈도 (NFR-01·02)
- 단건 진단 p95 2초(현재 실측 약 0.1초). 기동 직후에는 `GET /v1/readiness` 가 `ready` 일 때만 요청한다. 준비 중이면 503(G0).
- 영상·카메라 실시간 진단은 **1초에 1장, 요청은 한 번에 1건**(응답을 받은 뒤 다음 장)을 권장한다. 요청마다 집계 기록이 남는다.
- 검출기가 Ollama 비전 모델이면 첫 요청이 10~30초 걸릴 수 있다. `readiness.detector.load_seconds` 로 확인한다.

## 8. 후속 차량 (UC2, 실제 대전 BIS) — 보는 쪽은 카메라 번호가 필요 없다
- 식별자는 BIS 체계다: `route_id` = 노선 코드(102번 = `30300037`), `stop_id` = `노선코드:정류소ID`(충남대학교 (홈플러스유성점 방면) `30300037:42620`, 충남대학교 (온천교 방면) `30300037:42600`). 차량 번호는 BIS 표기(`대전75자9022`). **코드를 외울 필요 없다** — `/v1/reference/routes?q=102`, `/v1/reference/stops?q=충남대` 로 이름으로 찾는다. 대전 전체 노선 141개·정류장 10,533곳이 적재돼 있다.
- 도착 예정 시각은 **UTC** 다. 화면에는 한국 시각(+9시간)으로 바꿔 보인다.
- 실측이 있는 차량만 인원 / 정원·등급·잔여 %가 온다(`basis_type: measured`). 통계로 추정한 값은 주지 않는다(BR-CV-13). 특정 버스는 `/v1/vehicles/{차량 번호}` 로 바로 본다.

## 9. 안내 문구 (OR-03 낙인 방지)
- "실측 없음"은 "정보 없음"으로, "조회 불가"는 "운행 정보 연결 지연"으로 표시한다. 특정 노선·역을 부정적으로 단정하는 문구를 쓰지 않는다.
- 권장 예: "접근 차량 32 / 80명(혼잡 40%), 4분 뒤 후속 차량 12 / 80명(착석 가능)".
