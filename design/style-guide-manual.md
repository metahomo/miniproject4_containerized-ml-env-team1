## 2. 파일 구성

```
design/
├── style-guide.html        시각 가이드. 브라우저로 열어 색·글자·부품을 눈으로 확인하고 토큰을 복사한다
├── style-guide-manual.md   이 문서. 규칙과 사용 절차
└── DESIGN.md               getdesign 원본. YAML 토큰 + 산문 설명. 코딩 에이전트가 참조하는 정본
```

**역할 분담**

- **DESIGN.md** 가 정본이다. 값이 충돌하면 DESIGN.md 를 따른다.
- **style-guide.html** 은 DESIGN.md 를 CSS 변수와 실제 렌더링으로 옮긴 것이다. 여기서 본 것이 곧 구현 결과다.
- **이 매뉴얼**은 "어떻게 쓰나"를 다룬다. 값은 반복하지 않는다.

**열어 보는 법**: `style-guide.html` 을 브라우저에서 직접 열면 된다. 외부 자원 없이 동작하며 서버가 필요 없다. 스와치를 클릭하면 `var(--color-...)` 가 클립보드에 복사되고, 맨 아래 "토큰 전체 복사" 버튼으로 `:root` 블록을 통째로 가져갈 수 있다.

## 3. 새 화면을 만드는 순서

1. **구간을 먼저 나눈다.** 화면을 위에서 아래로 "타일"로 쪼갠다. 밝은 타일(white 또는 parchment)과 어두운 타일(tile-1)을 교대시킨다. 타일 사이 간격은 0 이고 배경색 변화가 구분선이다.
2. **타일마다 내용 순서를 고정한다.** 헤드라인(display-lg) → 한 줄 부제(lead) → 행동 버튼 1~2개(pill) → 콘텐츠. 이 순서를 바꾸지 않는다.
3. **글자 토큰을 고른다.** `.t-*` 클래스 중 하나를 붙인다. 크기·굵기·행간·자간을 직접 쓰지 않는다.
4. **색은 변수로만 쓴다.** `var(--color-primary)` 처럼 참조한다. hex 를 코드에 직접 적지 않는다.
5. **부품을 고른다.** §5 표에서 목적에 맞는 클래스를 고른다. 새 부품이 필요하면 기존 문법(hairline 카드, pill 버튼, sm 유틸리티)을 조합해서 만든다.
6. **반응형을 확인한다.** 640px 과 833px 에서 한 번씩 본다. 터치 타깃 44px 이상.
7. **그림자를 검사한다.** 카드·버튼·글자에 그림자가 있으면 지운다. 그림자는 제품 이미지에만 허용된다.

## 4. 토큰 사용법

### 4-1. 붙이기

`style-guide.html` 의 `<style>` 상단 `:root { ... }` 블록을 프로젝트 전역 CSS 에 복사한다. 또는 페이지 하단 "토큰 전체 복사" 버튼을 쓴다.

### 4-2. 이름 규칙

| 접두어 | 종류 | 예 |
|---|---|---|
| `--color-*` | 색 | `--color-primary`, `--color-canvas-parchment` |
| `--status-*` | 혼잡 등급 상태 색 (프로젝트 확장) | `--status-free`, `--status-crowded` |
| `--font-*` | 글꼴 스택 (둘 다 나눔바른고딕) | `--font-display`, `--font-text` |
| `--space-*` | 간격 | `--space-lg` (24px), `--space-section` (80px) |
| `--rounded-*` | 모서리 | `--rounded-sm` (8), `--rounded-lg` (18), `--rounded-pill` |
| `--shadow-product` | 그림자 (유일) | 제품 이미지 전용 |
| `.t-*` | 글자 스타일 클래스 | `.t-body`, `.t-display-lg` |

### 4-3. 글자

`.t-*` 클래스는 `font` 축약형으로 크기·굵기·행간·글꼴을 한 번에 지정한다. 자간은 별도 속성이다. 클래스 하나만 붙이면 끝이고, 개별 속성을 덧씌우지 않는다.

```html
<h2 class="t-display-lg">후속 차량 여유도</h2>
<p class="t-body">이 수치는 통계적 추정치입니다.</p>
<span class="t-caption">실측 09:41</span>
```

기본 `body` 에 `.t-body` 값이 이미 적용되어 있으므로 문단은 클래스 없이도 17px 이 된다.

### 4-4. 글꼴: 나눔바른고딕 통일

모든 글자는 **나눔바른고딕** 하나다. Display 와 본문을 구분하지 않는다(`--font-display` 와 `--font-text` 는 같은 값이다).

- **로드**: 네이버가 배포하는 woff 파일을 `@font-face` 로 300(Light) / 400(Regular) / 700(Bold) 세 굵기를 `NanumBarunGothic` 한 이름에 묶어 선언했다. `style-guide.html` 상단 블록을 그대로 복사한다.
- **네이버 기본 CSS 를 쓰지 않는 이유**: `nanum-barun-gothic.css` 는 굵기마다 family 이름이 다르다(`NanumBarunGothic`, `NanumBarunGothicBold`, `NanumBareunGothicLight`). 그대로 쓰면 700 이 합성 굵기로 렌더되어 흐려진다.
- **굵기 매핑**: Apple 원본의 600 은 700 으로 옮겼다. 나눔바른고딕 사다리는 300 / 400 / 700 이며 500·600 은 없다.
- **자간**: Apple 의 음수 자간 값을 그대로 유지했다. 한글이 지나치게 붙어 보이면 Display 크기에서만 자간을 0 으로 완화한다.
- **오프라인 시연**: 발표장 네트워크가 불안하면 woff 세 파일을 `design/fonts/` 에 받아 두고 `@font-face` 의 URL 을 상대 경로로 바꾼다. 스택 뒤의 `system-ui` 덕에 로드 실패 시에도 깨지지는 않는다.
- **라이선스**: 나눔 글꼴은 SIL Open Font License 로 상업·비상업 모두 무료다.

### 4-5. 어두운 배경

어두운 타일 안에서는 컨테이너에 `.on-dark` 를 붙인다. 글자색, 링크색(Sky Blue), 코드 배경이 함께 바뀐다. Action Blue 버튼은 어두운 배경에서도 그대로 쓴다. 텍스트 링크만 `.text-link-on-dark` 로 바꾼다.

## 5. 컴포넌트 선택표

### 5-1. 버튼

| 상황 | 클래스 | 이유 |
|---|---|---|
| 화면의 주요 행동 (조회, 저장, 상세 보기) | `.btn-primary` | pill + Action Blue 가 브랜드 행동 신호 |
| 주요 행동 옆의 두 번째 선택 | `.btn-secondary` | 같은 pill 문법, 투명 배경 ghost |
| 히어로 한 곳의 큼직한 CTA | `.btn-store-hero` | 18px/300, 드물게만 |
| 로그인·언어·설정 같은 유틸리티 | `.btn-dark-utility` | 8px 직각. 행동이 아닌 도구 |
| 카드 안의 작은 보조 동작 | `.btn-pearl` | 11px, Pearl 배경 |
| 사진·지도 위 원형 컨트롤 | `.btn-icon` | 44px 원, 반투명 회색 |
| 문장 속 링크 | `.text-link` / `.text-link-on-dark` | 배경별로 파란색 종류가 다름 |

눌림 상태는 전부 `scale(0.95)` 로 통일되어 있다. Hover 는 정의하지 않는다. 포커스는 2px Focus Blue 외곽선.

### 5-2. 컨테이너

| 상황 | 클래스 | 규칙 |
|---|---|---|
| 화면의 큰 구간 | `.product-tile` (+ `.parchment` 또는 `.tile-dark.on-dark`) | 모서리 0, 수직 여백 80px, 중앙 정렬 |
| 목록 속 항목 카드, 관리 메뉴 카드 | `.utility-card` | white + 1px hairline + 18px + 24px 패딩, 그림자 없음 |
| 차량 한 대의 진단 결과 | `.vehicle-card` | utility-card 문법 + 큰 숫자 + 상태 표시 |
| 선택 가능한 옵션 | `.chip` / `.chip.selected` | pill, 선택 시 2px Focus Blue |
| 검색 | `.search` | pill, 44px |
| 스크롤 중 따라오는 요약 + 행동 | `.sticky-bar` | Parchment 80% + blur, 64px |

### 5-3. 내비게이션

두 줄이 기본이다. `global-nav` 44px 검정(서비스 이름 + 최상위 메뉴), `sub-nav` 52px 반투명(현재 화면 이름 + 하위 메뉴 + 우측 주요 버튼). 833px 이하에서 global-nav 메뉴는 숨기고 sub-nav 는 이름과 버튼만 남긴다.

### 5-4. 푸터

Parchment 배경, 열 제목 `caption-strong`, 링크 `dense-link`(행간 2.41), 맨 아래 법적 문구 `fine-print` + `ink-muted-48`. 푸터는 의도적으로 밀도가 높은 유일한 구역이다.

## 6. 프로젝트 확장: 혼잡 등급 상태 색

DESIGN.md 에는 없는 토큰이다. Apple 원칙은 액센트 하나지만, 이 서비스는 등급을 시각으로 구분해야 해서 상태 색 5개를 추가했다.

| 등급 | 토큰 | 값 | 명세 근거 |
|---|---|---|---|
| 여유 | `--status-free` | #1d9a4f | FR-06 3단계 등급 |
| 보통 | `--status-normal` | #c98a00 | FR-06 |
| 혼잡 | `--status-crowded` | #d0342c | FR-06 |
| 판독 불확실 | `--status-uncertain` | #7a7a7a | FR-09, UC3 |
| 실측 없음 | `--status-none` | #cccccc | FR-13 근거 유형 |

**규칙**

1. 상태 색은 **정보 표시에만** 쓴다. 점, 글자, 배지, 게이지. 클릭 가능한 요소(버튼, 링크, 칩)에는 절대 쓰지 않는다. 클릭은 여전히 Action Blue 하나다.
2. 상태를 색만으로 전달하지 않는다. 항상 글자("혼잡", "판독 불확실")를 함께 둔다. 색약 사용자와 흑백 인쇄를 위한 규칙이다.
3. 판독 불확실은 회색이다. 경고색(노랑·주황)을 쓰지 않는다. "모르겠다"는 상태이지 "위험"이 아니기 때문이고, 명세가 억지 수치 대신 정직한 실패를 원칙으로 삼기 때문이다.
4. 판독 불확실의 수치는 "참고 40%" 처럼 작게(28px) 회색으로 쓴다. 확정값과 시각적으로 구분한다.
5. 실측 없음은 숫자 자리에 "—" 를 두고 등급 칸을 비운다. 통계 추정치를 채우지 않는다(명세 Clarifications Q1).
6. 추정치 고지(FR-10)는 `.t-fine-print` 로 카드 하단 또는 화면 하단에 항상 노출한다.
7. 시연 모드 표시(FR-13d)는 `.badge` 로 카드마다 붙인다.

`style-guide.html` §06 에 차량 카드 4종(혼잡·여유·판독 불확실·실측 없음)이 예시로 있다. 시연 웹 장면 2~5 에 그대로 쓴다.

## 7. 규칙 요약

### 지킨다

- 상호작용 색은 `--color-primary` 하나.
- 본문 17px / 400 / 1.47. 16px 아님.
- 글꼴은 나눔바른고딕 하나. 헤드라인 700, 음수 자간.
- 굵기 사다리 300 / 400 / 700. 500·600 없음.
- 모서리 문법 셋: sm(8) 유틸리티, lg(18) 카드, pill 행동. md(11) 는 Pearl 버튼에만.
- 그림자는 제품 이미지에만. 값은 `--shadow-product` 하나.
- 구간 구분은 배경색 교대로. 선·그림자 없음.
- 모든 버튼 눌림 `scale(0.95)`.
- 터치 타깃 44px 이상.

### 하지 않는다

- 두 번째 액센트 색. 상태 색을 버튼에 쓰는 것.
- 카드·버튼·글자 그림자.
- 장식 그라디언트.
- 타일 모서리 둥글리기.
- 본문 행간 1.47 미만.
- Sky Blue 를 밝은 배경에.
- Hover 상태 문서화.
- hex 직접 입력.

## 8. 갱신 절차

### 8-1. 토큰 값을 바꿀 때

1. `DESIGN.md` 의 YAML 값을 먼저 고친다. 정본이기 때문이다.
2. `style-guide.html` 의 `:root` 에서 같은 변수를 고친다.
3. 해당 스와치·표의 표기값(hex 글자)을 맞춘다.
4. 브라우저에서 열어 확인한다.
5. 이 매뉴얼 상단 버전을 올리고 아래 변경 이력에 한 줄 적는다.

### 8-2. 컴포넌트를 추가할 때

1. 기존 문법으로 조합이 불가능한지 먼저 확인한다. 대부분은 utility-card 나 pill 버튼의 변형으로 해결된다.
2. `DESIGN.md` `components:` 에 항목을 추가한다. 배경·글자·글자 토큰·모서리·패딩을 `{token.ref}` 형식으로 쓴다.
3. `style-guide.html` 에 CSS 클래스와 §05 데모를 추가한다.
4. 이 매뉴얼 §5 표에 "상황 → 클래스 → 이유" 한 줄을 추가한다.

### 8-3. getdesign 을 다시 실행할 때

`npx getdesign@latest add apple` 은 `DESIGN.md` 를 덮어쓴다. §6 확장 토큰과 프로젝트 주석이 사라지므로, 실행 전에 현재 `DESIGN.md` 를 백업하고 실행 후 §6 내용을 다시 넣는다. 상태 색 5개는 `colors:` 아래에 `status-*` 키로 추가한다.

### 8-4. 다크 모드

DESIGN.md 는 Apple 의 밝은 기본 모드만 분석했다(Known Gaps). 현재 가이드도 밝은 모드 하나다. 다크 모드가 필요해지면 `tile-1`~`tile-3` 을 canvas 로, `on-dark` 를 body 로 바꾼 `@media (prefers-color-scheme: dark)` 블록을 `:root` 아래에 추가한다. 상태 색은 어두운 배경에서 한 단계 밝게 조정해야 한다.

## 9. 자주 하는 실수

| 실수 | 왜 문제인가 | 고치는 법 |
|---|---|---|
| 혼잡 등급 색으로 버튼을 만든다 | 액센트가 둘이 되어 "클릭 가능"의 신호가 흐려진다 | 버튼은 Action Blue, 등급은 옆에 점·글자로 |
| 카드에 `box-shadow` 를 넣는다 | 시스템에 그림자는 하나뿐이고 그것은 제품 이미지용이다 | hairline 1px 테두리로 바꾼다 |
| 본문을 16px 로 쓴다 | 17px 이 이 언어의 읽기 속도를 정한다 | `.t-body` 사용 |
| 헤드라인에 600 을 쓴다 | 나눔바른고딕에 600 이 없어 합성되거나 400 으로 떨어진다 | `.t-display-lg` (700) 사용 |
| 네이버 기본 폰트 CSS 를 link 로 넣는다 | 굵기별 이름이 달라 Bold 가 합성 굵기로 렌더된다 | 가이드 상단 `@font-face` 블록 복사 |
| 카드 모서리를 12px 로 쓴다 | 문법에 없는 값. sm(8)/lg(18) 중 하나여야 한다 | 카드는 `--rounded-lg` |
| 섹션 사이에 `<hr>` 이나 선을 넣는다 | 구분은 배경색 교대가 한다 | 인접 타일의 배경을 다르게 |
| 어두운 타일에서 링크를 #0066cc 로 쓴다 | 어두운 배경에서 사라진다 | `.text-link-on-dark` (Sky Blue) |
| 판독 불확실을 노란 경고색으로 그린다 | "모름"을 "위험"처럼 보이게 해 명세의 정직한 실패 원칙과 어긋난다 | `--status-uncertain` 회색 + 글자 |
| 실측 없음에 평균값을 채운다 | 명세가 통계 추정을 금지한다(Q1) | "—" 와 "실측 없음" |
| Hover 색을 정의한다 | 이 시스템은 기본·눌림 두 상태만 가진다 | `:active` 의 scale 만 |
